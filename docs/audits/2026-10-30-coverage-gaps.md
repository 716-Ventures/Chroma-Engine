# Engine error-path coverage — 2026-10-30

Follow-up to the throughput/test audit. No Apple TV, production source, or running service was accessed or changed.

Added four synthetic regression tests in `src/container/mp4/dolby_recovery.rs`:

- Sample recovery reads at most the first two samples, supports fixed-size samples and 64-bit offsets, and respects a shorter sample count.
- Every truncation of a complete sample-table fixture is rejected. Missing chunk/mapping entries, a first mapping that starts after chunk one, and a wrong sample-description index are rejected.
- NAL-count, RPU-size, forbidden-bit, temporal-ID and oversized/truncated length limits reject malformed packets.
- Overlay preparation errors (empty, invalid, incomplete and missing sources) publish no header and never modify the input.

The mapping-entry regression exposed a real missing check: recovery read a first `stsc` entry even when its declared entry count was zero. The parser now requires a nonzero mapping count before reading it. No valid media path changes.
